# Review 0006: M1.5, sessions and the cookie carrier

| | |
|---|---|
| Date | 2026-11-15 |
| Under review | The M1.5 diff (`Load`, `Require`, `Check`, `Within`, `SignOut`, `Revoke`, `RevokeUser`, `Sessions`, `Sweep`), with interface §4.4, §5.6.1–4 and 10, §5.7.9, §5.9 and §7's session tests |
| Reviewer | Gemini 4 Argon (High) through agy, about 77k tokens |
| Triage | Claude |

Twelve findings: nine accepted, two in part, one rejected. Every accepted
finding about behaviour has a test that fails without its fix.

| # | Finding | Severity | Triage |
|---|---------|----------|--------|
| 1 | `Load` read a session, then wrote its `Seen` in a separate transaction; a session revoked in between was still admitted, and a failed write didn't matter | Critical | **Accepted.** The write reports whether the token still names a live session, judged at one reading of the clock; if not, or if the write fails, the request has no session. A test revokes the session between the read and the write |
| 2 | A request with a bearer header and a session cookie: signing in or out didn't end the cookie session it carried | Critical | **Accepted.** `Load` keeps the carried cookie session aside; such a request isn't signed in through it, but `Finish` of a `SignIn` and `SignOut` end it (amendment A8) |
| 3 | A `Level` other than the two counted as a level, so it dropped the default `Verified` and then passed | Major | **Accepted.** It is never met |
| 4 | `Load(Bearer())` inside `Load(Cookie())` saw the outer cookie session | Major | **Accepted.** `Load` replaces what an outer one attached |
| 5 | Only the first `Authorization` header was read, and `Bearer` with no token skipped the cross-origin check | Major | **Accepted** |
| 6 | No test left a remembered session idle to `session.remembered_idle` | Major | **Accepted.** A test |
| 7 | `Sweep` decoded each record twice and held one write transaction for the whole run | Major | **Accepted in part.** It decodes what the scan returns and checks the context as it goes. One transaction stays: an hourly sweep of a store this size is short, and the review's worry about keys was unfounded, since `store.Scan` hands out copies |
| 8 | `Sessions` with an empty or overlapping ID could read other users' index entries | Major | **Accepted in part.** The prefix ends with a zero byte, so IDs don't overlap; an ID the directory couldn't have returned now lists nothing |
| 9 | `SignOut` cleared the cookie before ending the session, so a failure left a live session the browser had forgotten | Minor | **Accepted.** The cookie is cleared once the session has ended |
| 10 | An unparsable peer address put every such client in one throttle bucket | Minor | **Rejected.** A request without an address is counted against the user alone (§5.8.9); there is no shared bucket |
| 11 | `Require(nil)` failed only when a signed-in request arrived | Minor | **Accepted.** `Require` panics when routes are built; `Check` returns an error before looking at the session |
| 12 | Weak assertions: the bearer exemption, `Require()` over HTTP with a verified session, the session ID after signing in again, a throttled request through `Load` | Minor | **Accepted.** Each test now asserts the outcome |

Mutation checks: each of 22 rules of the first pass and 11 of the fixes,
removed in turn, fails a test. One more, logging a failed write of `Seen`
instead of refusing, is equivalent: the write then reports the session
dead, which refuses too.
