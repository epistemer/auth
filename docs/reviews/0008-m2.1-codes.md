| # | Finding | Severity | Triage |
|---|---------|----------|--------|
| 1 | A code no one was sent (no address, a directory error, past `code.hourly`) was stored with a real MAC: guessable with every new flow, and for an unknown login a lucky guess reached the directory | Critical | **Accepted.** I had removed the random MAC myself when a mutation of it survived, judging it equivalent; it wasn't. It is back, an unknown login's code never verifies, and a test tries every code against an unsent one |
| 2 | `SentTo` was filled before the first proof in flows other than `SignIn` | Critical | **Accepted.** It is empty until the flow holds a proof or is bound to a session |
| 3 | Two factors need a first proof from `WithFirst`, so a `Recover` proved by codes can't be verified | Major | **Deferred to M2.2**, which defines what `Recover` needs |
| 4 | Addresses are stored as an unkeyed SHA-256, which a phone number's small space lets anyone reverse | Major | **Accepted in part.** An address that folds to nothing now has no hash. A keyed hash would break the comparison of a session's factors after the secret is rotated, and the store already holds client addresses and user IDs; §8 has it backed up like the database |
| 5 | `code.hourly` was a fixed window, allowing twice the limit across its edge, and a failed send counted | Major | **Accepted.** A sliding hour over the sends' times; a failed send is taken back |
| 6 | Past `code.hourly` a resend kept the old code, unlike every other case, which replaced it | Major | **Accepted.** Every `Challenge` past `code.resend` replaces the code |
| 7 | Offers drop a proven method by name, not by address | Major | **Rejected.** The directory gives one address per channel, so two methods never share one; links come with M2.2 |
| 8 | A disabled user's right code burns it; tries are counted for a missing or used code | Major | **Rejected.** Both are the strict side, and the second answer reveals nothing the first didn't |
| 9 | Tests that would pass with their rule broken: the second use never reached the code, the cancelled code was checked only if the draws differed, acceptance tests counted events not messages, no `Recover` | Major | **Accepted,** but `Recover`, which comes with M2.2. The second use is now made with the view from before the first, as a racing request would |
| 10 | `Challenge` asks the directory for the address twice | Minor | **Rejected.** A failed second lookup sends nothing and answers alike, as §5.1.5 wants |
| 11 | Two tests could fail by chance | Minor | **Accepted** |
| 12 | `mask` didn't trim, and showed `s•••@` for an address with no domain | Minor | **Accepted** |
