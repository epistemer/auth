# Review 0012: M3.2, refresh tokens and Reissue

| | |
|---|---|
| Date | 2026-11-16 |
| Under review | The M3.2 diff, with interface §5.6, §4.4 and §7's bearer lines |
| Reviewer | Gemini 4 Argon (High) through agy, about 72k tokens |
| Triage | Claude |

Nine findings: seven accepted, one in part, one rejected in part.

| # | Finding | Severity | Triage |
|---|---------|----------|--------|
| 1 | Within the grace, a replaced token returned its successor even after the successor had been used, so a thief could walk the chain of successors and never trip reuse | Critical | **Accepted.** The grace returns a successor only while it is unused, and rotating a successor wipes its predecessor's sealed copy |
| 2 | A refresh token from before a step-up was deleted, so its reuse went unnoticed | Critical | **Accepted.** A step-up marks the session's tokens used: one used again is reuse, which ends the session |
| 3 | Reuse was judged after the directory and the `Claimer`, so either failing let a replay pass without ending the session | Critical | **Accepted.** Reuse is judged first, in a transaction of its own |
| 4 | Sealed successors stayed for the session's life | Major | **Accepted.** `Sweep` wipes them past the grace |
| 5 | A dead session reached the directory before being refused; concurrent refreshes could write older claims last | Major | **Accepted in part.** A dead session is refused first. The claims race is rejected: claims are a display cache (§5.6.9) |
| 6 | `Reissue` trusted the caller's user before reading the session, and left the caller's `Session.Claims` stale | Major | **Accepted** |
| 7 | Tests that would pass with their rule broken | Major | **Accepted** |
| 8 | `Refresh` wrote `Seen` on every call | Minor | **Accepted** |
| 9 | An unused error | Minor | **Accepted** |

Found on the way: the in-transaction re-check of a replaced token treated
two refreshes racing with one token as reuse. That is a client asking
twice: within the grace it now gets the same successor, and outside it,
reuse. A test hook drives the race.

Mutation checks: each of 10 rules of the first pass and 10 of the fixes,
removed in turn, fails a test, but one equivalent: the check that a grace
successor is unused, which the wipe of its sealed copy also enforces.
