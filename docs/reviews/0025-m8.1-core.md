| # | Finding | Severity | Triage |
|---|---------|----------|--------|
| 1 | Two proofs racing on one `SignInWithout` flow, one naming a user and one unlinked, could leave the user's proof in a flow `Link` then gave to a new user | Major | **Fixed.** A proof's transaction refuses a flow holding an identity, and keeps an identity only in a flow that still knows no one (`ErrMethodUnavailable`, the count taken back); `Link` refuses a flow that knows someone or isn't a `SignInWithout` (`TestLinkRaces`, both orders) |
| 2 | The new-to-auth check scans every link and flow under the write lock | Major | **Fixed in part.** It stops at the first match. An index by user was declined for now: links and flows expire within the hour and `Sweep` removes them, and the routes that make them are rate-limited by the app |
| 3 | A second proof of a method in one flow kept the first's empty address | Minor | **Fixed**: the address is kept once either proof gave one. A method already proved isn't offered again, so no test reaches it |
| 4 | A result naming a user and an unlinked identity was taken as the user's | Minor | **Fixed**: it is the method's own failure |
| 5 | `isIdentity` might count a passkey | Minor | **Declined**: a passkey is a second method, so never an identity; `TestUnlinkEdges` pins it |

The reviewer found these hold up: the new-to-auth check in the
transaction that links, against races with `Link`, `Recover`, `Invite`,
`SetPassword` and new sessions; an unlinked flow taking no other proof;
`AddressOnly`; `Unlink` bound to the session's user and refusing the last
way in; the address carried through `Link`; no secret in events.

Each fix has a test that fails without it; with M8.1's own 26 mutations,
31 in all, every one caught.
