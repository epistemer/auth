# Review 0027: M8.4, the security review of v0.3.0

| | |
|---|---|
| Date | 2026-11-17 |
| Under review | Everything added since v0.2.0, without tests or generated code: the core's identities (M8.1), `auth/oidc` (M8.2), `authschema.OIDC()` and the shop's provider routes (M8.3); with the contract (§4.12, §5.5, §5.7, §5.8, §5.14, D42–D45, A22, A25–A27) |
| Reviewer | Gemini 4 Hydrogen (XHigh) through agy, about 505k tokens, at the highest effort available (Argon is out of quota). A first call was cut off and run again |
| Triage | Claude |

Twelve findings: nine fixed, two fixed in part, one declined. The fixes
were not sent back for a check: each is pinned by a test that fails
without it, checked by mutation (19 mutations, every one caught).

| # | Finding | Severity | Triage |
|---|---------|----------|--------|
| 1 | On a `SignInWithout`, an attacker's own trusted device made their attempts count on its pair alone, and their own success cleared it: unlimited attempts from one address | High | **Fixed**: a proof on a flow that named no user when it was counted clears no counter (`TestDeviceSuccessClearsNothing`) |
| 2 | An identity's proof of one factor, made silently on a weeks-old session at the provider, met `Within` and §5.1.9; `Link` dated the proof when it linked | High | **Fixed**: such a proof meets no `Within` and is no fresh proof for changing factors, as a device isn't; a proof of two factors keeps its five-minute `auth_time`; `Link` keeps the proof's own time (`TestIdentityFreshness`) |
| 3 | A flow proved with a credential could still `Finish` after the credential was removed, unlinked or reset (passkeys and authenticator apps too) | High | **Fixed**: a proof records the credential it used, and `Finish` checks it is still the user's, in its transaction; an authenticator app's proof checks the user still has one (`TestFinishNeedsTheCredential`) |
| 4 | `Unlink` panicked on a method name with a zero byte | High | **Fixed**: the name must be a method's name |
| 5 | The shop's `GET /sign-in/oidc` let any page start flows and replace the flow cookie; the callback finished without a second proof; a failed `Link` left its new user behind | High | **Fixed**: the button is `POST /sign-in/oidc`, `no-store` on both; the callback asks for a second proof as after a password; a user made for a refused `Link` is removed. Case-folding logins is an app's directory's own |
| 6 | One key go-jose can't read (X25519, `oct`) dropped the whole key set | Medium | **Fixed**: keys are read one by one, the unreadable skipped |
| 7 | Within the minute after a failed key fetch, valid tokens were refused as bad | Medium | **Fixed**: the failure stays the answer until the next fetch is due |
| 8 | No block on private addresses; an https issuer on localhost allowed http endpoints | Medium | **Fixed in part**: http endpoints only beside an http issuer on localhost. Private addresses declined again (review 0026) |
| 9 | `Rekey` and `New` read a module's pending credential as a sealed authenticator secret, failing and logging falsely | Medium | **Fixed**: only an authenticator app's enrollment is read |
| 10 | A long code made the provider fail, answered as an outage that takes back the count | Medium | **Fixed**: a code past 4 KiB is `malformed`, before the exchange |
| 11 | A code to the mailbox the identity showed was offered as a second proof, though it makes one factor with it | Medium | **Fixed**: it isn't offered; with nothing else the user can't verify (`ErrCannotVerify`), and `Link` refuses such a user before storing anything |
| 12 | Smaller: a `Challenge` racing an unlinked proof; `Link`'s restart keeping state; ended sessions unseen by the new-to-auth check; full scans; `Link` storing before `ErrCannotVerify` | Low | **Fixed in part**: the race and the state, and `Link` (11). Ended sessions: their index by user goes when they end, so the check sees live sessions, devices and every credential; A28 says so. Full scans declined again (review 0025) |

The reviewer found these hold up: the ID token and callback checks,
identities isolated by issuer, subject and method, one-time state and the
credential checked in the write transaction, the binding of `Link` to the
flow's own identity, the mailbox rule, secrets kept out of errors and
events, and the client's redirects, timeout and cap.
